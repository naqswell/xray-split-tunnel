# Безопасность

## Поддерживаемая версия

Исправления безопасности выпускаются только для последнего опубликованного
релиза. До появления опубликованного version tag передавайте репозиторий как
архив с отдельно переданной SHA-256-суммой и фиксируйте точный commit в акте
передачи. Release-процедура проверяет exact tag, SHA-256 и provenance в
`REVISION`, но не заявляет и не проверяет криптографическую подпись тега.

## Как сообщить об уязвимости

Не создавайте публичный issue, если сообщение содержит subscription URL,
VLESS/Reality-параметры, внутренние домены, адреса шлюзов, логи Citrix или
сертификаты. Передайте краткое описание сопровождающему тем же закрытым
каналом, по которому был получен релиз. Приложите:

- версию macOS, xray-core и commit/tag репозитория;
- команду, на которой воспроизводится проблема, без секретных аргументов;
- минимальный обезличенный конфиг;
- ожидаемое и фактическое поведение.

Перед отправкой удалите или замените значения `id`, `publicKey`, `shortId`,
`serverName`/`sni`, subscription URL, внутренние FQDN и публичные IP.

## Что считается секретом

- URL подписки и ответ провайдера;
- активный `config.json`: он обычно содержит VLESS UUID и Reality-параметры;
- внутренние домены, CIDR и адреса шлюзов, если политика организации считает
  их конфиденциальными;
- Citrix client identity, её приватный ключ и экспорт `.p12`/`.pfx`;
- пароль Citrix и любые cookies/токены авторизации.

Рабочее состояние хранится в `~/.config/xray-split-tunnel/` с правами каталога
`0700` и файлов `0600`. Не переносите эти файлы в репозиторий и не прикладывайте
их к задачам AI-агента. Каталог и файлы обязаны принадлежать текущему
пользователю и не могут быть symlink. System plist — отдельный публичный
root-owned файл `0644`; user plist принадлежит пользователю и имеет `0600`.

Существующий произвольный непустой `XST_HOME`, foreign target plist/job или
XST-артефакт в противоположном launchd scope считается конфликтом владения и
не перезаписывается. Смена label/scope не выполняется неявно.

## Безопасная передача subscription URL

Не вставляйте URL в чат, shell-команду, переменную окружения процесса, issue
или CI secret, который печатается в лог. При agent-driven установке Claude сам
запускает:

```sh
./scripts/capture-sub-url.sh
```

Helper получает значение через скрытый системный диалог macOS, проверяет URL и
атомарно сохраняет `sub-url` с правами `0600` под operation lock. URL не
передаётся через argv/environment и не печатается. Для ротации используется
`./scripts/capture-sub-url.sh --replace`. Агент проверяет только наличие,
владельца и права файла и никогда не читает его содержимое.

Конфиденциальные bypass domains/CIDR для неинтерактивной установки также
передаются только через отдельный data-only файл `0600` вне `XST_HOME`.
`XST_BYPASS_DOMAINS` и `XST_BYPASS_CIDRS` через process environment
установщиком отклоняются.

Если URL уже появился в чате, истории shell, логе или публичной задаче,
считайте токен раскрытым: отзовите/перевыпустите подписку, замените локальный
файл и выполните `xst update`.

## Границы модели угроз

Сервис слушает только loopback и не открывает прокси в LAN. Он не защищает от
вредоносного процесса, уже работающего под тем же пользователем: такой процесс
может прочитать пользовательские файлы и обратиться к локальным портам.

Этот проект доверяет выбранному бинарнику xray-core, но рассматривает
subscription как недоверенный ввод. Из неё переносятся только allowlisted
proxy outbounds и provider block rules; provider direct/DNS/control outbounds,
inbounds, direct/block, DNS, logging, API, metrics и
остальная top-level политика создаются самим проектом. Каждый полученный
config проходит структурную проверку и `xray run -test`; выбранный входной
container больше чем с 512 candidate elements отклоняется до фильтрации как
DoS guard. Перед установкой проверяйте источник release-архива, его SHA-256 и
совпадение commit в manifest/`REVISION`.

Subscription скачивается только по HTTPS с HTTPS-only redirects, ограничением
10 MiB и очищенными proxy-переменными. URL передаётся curl как config stream
на stdin, а не process argv/environment; пользовательский `~/.curlrc`
отключён первым аргументом `-q`. Download и cookie jar создаются с `0600` и
удаляются trap-обработчиком. Конфиг собирается во временный файл и заменяет
рабочий только после проверки.

Внутренние домены и CIDR передаются между shell и Python через ограниченный
NUL-delimited stdin, а не через process argv. Это не меняет базовую границу
угроз: процесс того же пользователя всё равно может читать state и память.

`apply`/`update` сохраняют snapshot управляемых runtime-файлов и пытаются
вернуть его, если restart и доказательство процесса/listeners не прошли.
Install transaction включает state/plist, запуск, active hash, явно
разрешённый managed shell block и созданный ею command symlink. После записи
`applied.env` и signal-safe commit bookkeeping transaction считается
committed; затем lock снимается только с проверкой owner token. Ошибка снятия
lock, последующий провал `xst verify` и ручная Citrix acceptance уже не
запускают автоматический rollback. Неудачный rollback всегда требует ручной
диагностики; legacy `com.nqs.xray` восстанавливается только по
`docs/migration.md`.

Mutating-операции сериализованы fail-fast каталогом
`$XST_HOME/.xst-operation.lock` с правами `0700`. Неизвестный или stale lock
автоматически не удаляется, чтобы второй процесс не нарушил активную
транзакцию.

Routing strategy `IPIfNonMatch` может передать не совпавшее с domain bypass
имя системному resolver для проверки IP/CIDR-правил. Поэтому DNS-запрос такого
proxy-направления может быть виден macOS/Citrix DNS до соединения через XRay.
Этот проект не является DNS-privacy решением.

Citrix-пароль и client identity не принадлежат этому репозиторию. Их обработка
описана в соседнем `secure-access-helper` и в
`docs/citrix-prerequisites.md`.

Опциональные `claude-xst` и `claude-xst-aware` не изменяют глобальные
настройки Claude: proxy и NO_PROXY действуют только в запущенной сессии и
наследуемых subprocess. Базовая `claude-xst` не меняет контекст Claude.
Только `claude-xst-aware` добавляет короткую append-system-prompt инструкцию;
она не содержит bypass-значений или других секретов. Сторонний subprocess,
который игнорирует стандартные proxy environment variables или намеренно
очищает environment, остаётся вне гарантий explicit proxy-модели.
