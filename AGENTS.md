# Инструкция для AI-агента

Ты настраиваешь этот репозиторий на машине пользователя. Читай этот файл целиком
до первого действия. Человеческая документация — `README.md`, детали формата
подписки — `docs/subscription-format.md`.

## Что должно получиться

Локальный прокси xray-core под launchd: HTTP `127.0.0.1:10809` и SOCKS5
`127.0.0.1:10808`. Корп-домены пользователя и приватные подсети идут **мимо**
туннеля (`direct`), всё остальное — через сервер провайдера.

## Данные, которые нужно получить у пользователя

Спроси всё это **одним сообщением**, до начала установки:

1. **Subscription URL** провайдера (вид `https://<host>/connect/<токен>`). Это
   секрет: не печатай его в ответах, не пиши в файлы вне `~/.config/xray-split-tunnel/`,
   не коммить. Если пользователь не хочет диктовать — пусть положит сам:
   `mkdir -p ~/.config/xray-split-tunnel && chmod 700 ~/.config/xray-split-tunnel`,
   затем URL в файл `sub-url` (chmod 600), и скажет тебе «положил».
2. **Домены корпоративной сети**, которые должны ходить напрямую, суффиксами
   через запятую (`example.com,corp.local`). Если корп-VPN нет — пусть скажет явно,
   тогда разделения не будет и это нормально.
3. **Подсети** корп-сети вне RFC1918, если есть (обычно нет).
4. **Страна/сервер** — иначе бери первый в списке.

Не выдумывай значения. Не подставляй домены из чужих примеров.

## Порядок действий

```sh
cd <корень репозитория>
./install.sh                 # интерактивно, если пользователь у терминала
```

Если ты выполняешь установку сам, без интерактива:

```sh
XST_SUB_URL='<url>' \
XST_BYPASS_DOMAINS='example.com,corp.local' \
XST_SERVER=0 \
./install.sh --non-interactive
```

Переменные окружения (все опциональны, кроме источника подписки):

| Переменная | Смысл | Дефолт |
|---|---|---|
| `XST_SUB_URL` | URL подписки | — (или `XST_SUB_FILE`) |
| `XST_SUB_FILE` | локальный JSON вместо скачивания | — |
| `XST_SERVER` | индекс или подстрока названия | `0` |
| `XST_BYPASS_DOMAINS` | домены в обход, через запятую | пусто |
| `XST_BYPASS_CIDRS` | подсети в обход | пусто (приватные всегда) |
| `XST_HTTP_PORT` / `XST_SOCKS_PORT` | порты | `10809` / `10808` |
| `XST_LABEL` | launchd label | `com.xst.xray` |
| `XST_EXPORT_HTTPS_PROXY` | `1` — глобальный HTTPS_PROXY | `0` |
| `XST_ZSHRC` | `1` дописать в `~/.zshrc`, `0` не трогать | спросить |
| `XST_LINK_BIN` | `0` не делать симлинк `~/.local/bin/xst` | `1` |
| `XST_HOME` | другой каталог состояния (для теста) | `~/.config/xray-split-tunnel` |

Установщик идемпотентен — при ошибке правь причину и запускай снова.

## Как проверить, что получилось

```sh
xst verify     # или ./bin/xst verify
```

Успех = четыре блока без `✗`: конфиг OK, порты слушаются, IP через туннель
отличается от прямого, каждый bypass-домен резолвится в `direct` и присутствует
в `NO_PROXY`. **Не отчитывайся об успехе, пока `xst verify` не вернул 0.**

Дополнительно, если у пользователя есть корп-VPN: попроси его при поднятом
корп-клиенте открыть внутренний ресурс и подтвердить, что он работает. Ты сам
корп-адресов не знаешь и проверить это не можешь.

## Типичные проблемы

| Симптом | Причина и действие |
|---|---|
| `в подписке нет ни одного XRay-конфига` | провайдер отдаёт base64/`vless://`/sing-box → `docs/subscription-format.md`, конвертировать вручную, дальше `XST_SUB_FILE` |
| `не удалось скачать подписку` | ссылка протухла или нужен другой User-Agent (`SUB_UA` в `~/.config/xray-split-tunnel/env`) |
| `xray отверг конфиг` | покажи `xray run -test -config ~/.config/xray-split-tunnel/config.json` целиком, не глотай вывод |
| порт занят | другой прокси на 10809 → спроси у пользователя новый порт |
| IP совпадают | сервис не поднялся: `xst logs` |

## Границы

- **Не трогай** корпоративный VPN-клиент, его профили и учётные данные.
- **Не включай** глобальный `HTTPS_PROXY` без явной просьбы: это заворачивает в
  туннель весь CLI, включая корп-инструменты.
- **Не добавляй** в `BYPASS_DOMAINS` ничего, чего пользователь не называл.
- **Не публикуй** содержимое `~/.config/xray-split-tunnel/` — там URL подписки и
  ключи VLESS/Reality. При отправке логов в чат маскируй `id`, `publicKey`, `sni`.
- Правку `~/.zshrc` делай только с подтверждения (или `XST_ZSHRC=1`).

## Устройство репозитория

| Файл | Роль |
|---|---|
| `install.sh` | опрос + установка, 8 шагов, идемпотентен |
| `bin/xst` | управление после установки |
| `lib/xstlib.py` | вся логика над JSON: нормализация подписки, сборка конфига, инъекция правил, оффлайн-разбор маршрутизации |
| `lib/common.sh` | пути, логгеры, скачивание подписки, генерация `NO_PROXY` |
| `templates/launchagent.plist.template` | сервис |
| `uninstall.sh` | снятие (`--purge` — вместе с секретами) |

Логика разделения трафика — три слоя, менять надо все три согласованно
(`lib/xstlib.py:inject_rules`, `lib/common.sh:xst_write_shell_snippet`,
проверка в `bin/xst:cmd_verify`). Подробнее — `docs/how-it-works.md`.
