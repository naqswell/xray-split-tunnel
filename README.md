# xray-split-tunnel

Локальный прокси-канал на **xray-core** для macOS с **раздельным туннелированием**:
выбранные домены и подсети (корпоративный VPN, локальная сеть) ходят напрямую,
всё остальное — через VLESS/Reality-сервер провайдера.

Ставится одной командой: `./install.sh` спросит всё нужное и сам поднимет
launchd-сервис. Либо это может сделать AI-агент — ему адресован `AGENTS.md`.

```
приложение с HTTPS_PROXY=http://127.0.0.1:10809
      │
      ▼
 xray-core (launchd, KeepAlive)          конфиг: ~/.config/xray-split-tunnel/config.json
      │  HTTP 127.0.0.1:10809 · SOCKS5 127.0.0.1:10808
      │
      ├─ приватные подсети (10/8, 172.16/12, 192.168/16, loopback, link-local) ──► direct
      ├─ твои корп-домены (BYPASS_DOMAINS)                                     ──► direct
      └─ всё остальное                                        ──► VLESS+Reality ──► интернет
```

`direct` — это системный сетевой стек: если поднят корпоративный VPN-клиент
(Citrix Secure Access, GlobalProtect, любой L3-туннель), трафик уходит в него,
а не в зарубежный экзит.

## Требования

- macOS (Apple Silicon или Intel), протестировано на 15.x/26.x
- Homebrew (`install.sh` предложит поставить `xray` сам)
- python3 — системный, из Xcode CLT (`xcode-select --install`)
- **подписка VPN-провайдера, отдающая XRay JSON** — см. `docs/subscription-format.md`

## Установка

```sh
git clone <url-этого-репо> ~/Projects/xray-split-tunnel
cd ~/Projects/xray-split-tunnel
./install.sh
```

Скрипт спросит:

| Вопрос | Что отвечать |
|---|---|
| Subscription URL | ссылка провайдера вида `https://<host>/connect/<токен>` — та же, что вставляется в Happ/v2rayN |
| Сервер | индекс из показанного списка или часть названия («Финляндия») |
| Домены в обход | суффиксы корп-доменов через запятую: `example.com,corp.local` |
| Доп. подсети в обход | если корп-сеть не в RFC1918 — например `100.64.0.0/10`; иначе пусто |
| Порты, launchd label | можно оставить дефолт |
| HTTPS_PROXY глобально? | **по умолчанию нет** — безопаснее включать точечно через `xst run` |

Всё записывается в `~/.config/xray-split-tunnel/` (chmod 600). Повторный запуск
безопасен: прошлые ответы предлагаются как значения по умолчанию.

## Команды

```sh
xst status              # сервис, порты, активный сервер, правила обхода
xst list                # серверы из подписки
xst switch Финляндия    # переключиться (индекс или часть названия)
xst update              # перекачать подписку и переприменить текущий сервер
xst check corp.example.com   # куда пойдёт хост: direct или в туннель
xst run claude          # запустить команду с HTTPS_PROXY на туннель
xst verify              # полная проверка: конфиг, порты, IP, split tunnel
xst logs | xst restart | xst stop
```

## Как включить прокси для приложения

По умолчанию `HTTPS_PROXY` глобально **не** экспортируется — иначе в туннель
уедут все CLI-инструменты, включая те, что ходят в корп-сеть.

- разово: `xst run <команда>` (например `xst run claude`, `xst run curl https://...`)
- для конкретного приложения: `HTTPS_PROXY=http://127.0.0.1:10809 <команда>`
- глобально (осознанно): в `~/.config/xray-split-tunnel/env` поставить
  `EXPORT_HTTPS_PROXY="1"`, затем `xst apply` и новый терминал

`NO_PROXY` со списком твоих корп-доменов выставляется в shell всегда — это
первый слой защиты от утечки корп-трафика в туннель.

## Изменить список доменов в обход

```sh
$EDITOR ~/.config/xray-split-tunnel/env     # BYPASS_DOMAINS / BYPASS_CIDRS
xst apply                                    # пересобрать конфиг + NO_PROXY + перезапуск
xst check новый.домен.рф                     # убедиться, что → direct
```

## Проверка, что разделение реально работает

`xst verify` делает четыре вещи: валидирует конфиг через `xray run -test`,
смотрит порты, сравнивает внешний IP напрямую и через прокси (должны
различаться) и прогоняет каждый bypass-домен через оффлайн-разбор правил
маршрутизации (должен получиться `direct`) + проверяет его наличие в `NO_PROXY`.

Живая проверка корп-доступа (её нужно сделать руками, скрипт не знает твоих
внутренних адресов):

```sh
# при поднятом корп-VPN, из терминала с NO_PROXY:
curl -sI https://внутренний.корп.хост | head -1     # должен ответить
xst run curl -s https://api.ipify.org               # должен показать IP экзита
```

## Файлы

| Путь | Что |
|---|---|
| `~/.config/xray-split-tunnel/env` | параметры установки (label, порты, домены в обход) |
| `~/.config/xray-split-tunnel/sub-url` | URL подписки — **секрет** |
| `~/.config/xray-split-tunnel/subscription.json` | список конфигов провайдера — **секрет** |
| `~/.config/xray-split-tunnel/config.json` | активный конфиг xray — **секрет** |
| `~/.config/xray-split-tunnel/shell.sh` | сниппет с `NO_PROXY`, подключается из `~/.zshrc` |
| `~/Library/LaunchAgents/<label>.plist` | сервис |
| `~/Library/Logs/<label>.{out,err}.log` | логи |

В git не попадает ничего из этого: репозиторий содержит только код и шаблоны.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `порт не слушается` | `xst logs` — обычно битый конфиг или занятый порт; смени порт в `env` → `xst apply` |
| `IP совпадают` в verify | xray не поднялся либо приложение не использует прокси — проверь `xst status` |
| `не удалось скачать подписку` | провайдер требует cookie/UA — они уже учтены; проверь ссылку в браузере и `SUB_UA` в `env` |
| `в подписке нет ни одного XRay-конфига` | у провайдера другой формат — `docs/subscription-format.md` |
| корп-ресурс не открывается | `xst check <домен>` → если не `direct`, добавь суффикс в `BYPASS_DOMAINS` и `xst apply` |

## Удаление

```sh
./uninstall.sh            # сервис, plist, симлинк, строка в ~/.zshrc
./uninstall.sh --purge    # + секреты в ~/.config/xray-split-tunnel
```

## Не macOS

Логика (сборка конфига, правила маршрутизации, проверки) в `lib/xstlib.py`
платформонезависима. Привязано к macOS только оформление сервиса: launchd-plist
и `launchctl` в `install.sh`/`bin/xst`. Для Linux их заменяет systemd-юнит с тем
же `xray run -config <путь>`.

## Что сюда НЕ входит

Настройка самого корпоративного VPN-клиента. Этот репозиторий только следит,
чтобы корп-трафик не уходил в туннель xray.
